## 3. What went well

- **Verify-and-harden approach:** Both stories built on existing BlogSection behavior (empty/error already present). Work focused on AC verification: copy, a11y, rest-of-page usability, and tests—minimal rework, clear scope.
- **Consistent a11y pattern:** Empty and error states both use `<h2>` for the message so screen readers announce them; section keeps `aria-live="polite"`, `aria-busy`, `aria-label="Blog"`. Same pattern as Epic 3 pagination labels.
- **4.1 → 4.2 handoff:** 4.1 established empty as `<h2>` and test patterns; 4.2 applied same pattern for error, added retry and error-specific tests. No conflicting changes to blogApi or layout.
- **Code review value:** 4.2 review caught retry touch target (44px on mobile), retry aria-label "Retry loading posts", need for fetch rejection test, and Layout.css footer margin in File List. All addressed before done.
- **Test coverage:** Empty and error branches fully covered (success empty, error, success with posts; retry present and refetch behavior). Rejection path covered for error state.
- **Architecture alignment:** Single blog API module; in-section only for empty/error; no full-page takeover; design tokens and existing layout preserved.

## 5. Key insights and learnings

1. **Empty vs error separation:** Strict separation (empty = success + empty array; error = network/timeout/non-2xx) kept render order and tests clear. Single content type at a time (loading → list | empty | error) avoids edge-case bugs.
2. **Heading for a11y:** Using `<h2>` for empty and error messages (instead of `<p>`) gives screen readers a clear announcement without adding extra live regions. Matches NFR-A2 and stays simple.
3. **Retry via React Query:** Retry button wired to `refetch()` from `useQuery`; no new API layer. Same pattern could apply to other sections with async load.
4. **Code review catches UX details:** Touch target (44px) and aria-label for retry improved accessibility and were caught in review—worth keeping review checklist for a11y and mobile.
5. **Completion notes in AGENTS.md:** Epic 3 action item to document completion-notes convention is satisfied; AGENTS.md "Completion Notes (story work)" now guides behavioral/layout summary. Epic 4 story completion notes followed it.
