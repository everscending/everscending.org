## 5. Key insights and learnings

1. **React Query + queryKey:** Including `page` (and limit) in `queryKey` for the posts list made pagination refetch and cache behavior correct without extra logic. Same pattern as Epic 2 for server state.
2. **Page clamping when totalPages shrinks:** When API returns fewer total pages (e.g. content removed), current page must clamp to valid range so UI and API stay in sync. Code review caught this; good pattern for future pagination work.
3. **Pagination only when sensible:** Showing pagination only when `data?.ok === true` and `totalPages > 1`, and not in error state, avoids stale totalPages and confusing UI. Explicit condition in 3.2.
4. **DOMPurify for trusted source:** Even with trusted SonicJS API, sanitizing post body HTML before `dangerouslySetInnerHTML` is low-cost defense in depth; documented in 3.1 completion notes.
5. **Up-to-5 page window:** Centered window of page numbers with current page highlighted (aria-current + CSS) keeps UI compact and matches UX spec; tests for window behavior (e.g. totalPages=10) prevent regressions.
